**PaTorrent 1.1.0** adds a search box and importers from qBittorrent and µTorrent, hardens the engine, the Web UI and the remote mode after a security review of the whole code base, fixes what the author's hand test of 1.0.1 on Windows found, and puts icons beside the category list, the detail tabs, the Preferences pages and the Windows menus. It has been used mostly by its author so far, so reports of what breaks are very welcome.

PaTorrent (PatinaTorrent) is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.0.1

- **Search box.** Where µTorrent 2.2.1 had its web search, the toolbar now has a box that filters the torrent list by name as you type, on top of the category or label picked on the left. Ctrl+F jumps to it.
- **Import from qBittorrent and µTorrent.** File > Import reads qBittorrent's `BT_backup` folder or µTorrent's `resume.dat` and adds those torrents with their save folders, labels and settings. The other client must not be running; nothing of it is changed. The files are checked again after the import, rather than trusting the old client's records, and every file stays inside its save folder: the question before the import lists those folders. `patorrent-nox run --import` does the same for the daemon.
- **Security hardening.** A review of the engine, the Web UI, the remote mode, fetches and the Windows integration led to fixes across them. Among them: peers that never read, degenerate encryption keys and unbounded web-seed headers can no longer tie the client up; the DHT ignores replies from addresses it did not ask and refuses to be pointed at loopback or the LAN; trackers elsewhere cannot list peers on your machine, and no peer connections go to ports below 1024; seed mode checks each piece before uploading it; HTTPS needs TLS 1.2 and refuses revoked certificates; feeds and redirects cannot reach your local network unless you added that address yourself; cookies stay on their site; the Web UI bounds connections before login, bans per client, ends other sessions when the password changes and asks for the current password before its security settings change; random numbers come from a ChaCha20 generator seeded by the operating system, with no weak fallback.
- **Remote mode over HTTPS.** The GUIs connect to a `patorrent-nox` over HTTPS by default; plain HTTP to another computer needs your agreement first.
- **Windows fixes.** Stopped torrents no longer show their last speed; rows no longer go blank after hovering or Select All; the scheduler grid no longer flickers and uses µTorrent's colours; alternating row shading (Preferences > UI Settings, on by default); Ctrl+S, Ctrl+T, Ctrl+Shift+P and Enter for Start, Stop, Pause and Properties, shown in the menus; redrawn toolbar icons and a magnifier for the checking states.
- **Icons** beside the category list, the detail tabs and the Preferences pages (Windows and GTK), and beside the Windows menu commands.
- **Version strings.** A build that is not a tagged release shows `<version>-dev.<commit>` in its title bar, About box and `--version`, so test builds can be told apart.

Settings and torrents from 1.0.1 carry over unchanged.

**The remote protocol changed (version 9).** A GUI and a `patorrent-nox` must both be 1.1.0 to work together in the remote mode; update both.

The peer ID is now `-PA1011-` (it was `-PA1010-`): the engine's behaviour on the wire changed with the fixes above.

## First run

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Over an installed 1.0.1 it upgrades in place. Settings and torrents are in `%APPDATA%\PaTorrent`.
- **Windows zip.** Unzip anywhere and start `patorrent.exe` (SmartScreen as above). Settings and torrents go to `%APPDATA%\PaTorrent`; an empty `patorrent.ini` next to the exe keeps them beside it instead (portable mode).
- **Linux AppImage.** `chmod +x PaTorrent-1.1.0-x86_64.AppImage`, then run it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/patorrent/gtk`, torrents in `~/.local/share/patorrent/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user PaTorrent-1.1.0-x86_64.flatpak
  flatpak run io.github.balls0fsteel.PaTorrent
  ```

- **macOS.** Drag `PaTorrent.app` to Applications. It is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time ("cannot be opened because the developer cannot be verified"): right-click (or Control-click) the app > Open, then Open. Or remove the quarantine flag: `xattr -dr com.apple.quarantine /Applications/PaTorrent.app`. The GUI is Apple silicon only; Intel Macs get `patorrent-nox`.
- **Headless.** `patorrent-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080 (`--webui-https` for a self-signed certificate). `patorrent-nox add file.torrent --save DIR` adds a torrent. Running it as a service (systemd units, FreeBSD rc.d, `--daemon`, a Windows service) is described in [docs/DAEMON.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.0/docs/DAEMON.md).
- **Remote control.** Either GUI can drive a `patorrent-nox` elsewhere: File > Connect to Remote..., or start it with `--remote`. Both sides must be 1.1.0.

## Known limitations

- Most features have been exercised by the author only; some dialogs and settings have had little use. Keep a copy of torrents you care about elsewhere.
- **Do not use it on private trackers yet.** The client ID `PA` is not whitelisted anywhere.
- Nothing is code-signed: Windows SmartScreen and macOS Gatekeeper warn (see above).
- The search box and the importers are new and have had little hand testing; the importers have been tested against qBittorrent's and µTorrent's file formats, not yet against many real installations.
- The GTK GUI's new icons have been built and checked on CI but not yet looked at on a Linux desktop.
- macOS: the `.app` has only been built and started on GitHub's runners; it has not been used on a real Mac.
- The Linux AppImages and the Flatpak have had command-line smoke checks but little desktop use; the aarch64 builds are untried on real hardware.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/PaTorrent/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, the Logger tab or `patorrent-nox run --verbose` output helps. Security problems: see [SECURITY.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.0/SECURITY.md).
