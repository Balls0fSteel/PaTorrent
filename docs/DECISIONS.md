# Project decisions

Last updated: 2026-10-30_195156_1793386316

Active decisions D1-D45; D42 is proposed (below the table). D1-D26 were extracted from the [plan snapshot](archive/PLAN-2026-10-23.md); D27-D30 record the current artwork direction; D31-D33 the installer, the update check and the website; D34 the release path to 1.0; D35 the V1.1 scope; D39 the Web UI page of the Windows GUI (superseded by D40, the GUI serving the Web UI itself). Read the relevant rows when a task needs their rationale; [PLAN.md](../PLAN.md) is the current work summary.

> Implementation note: D3 records the approved write-back-cache design. The current implementation writes directly to files and has a per-disk-thread read cache; see [ARCHITECTURE.md](ARCHITECTURE.md) and [BACKLOG.md](BACKLOG.md#disk-and-storage). This extraction does not amend that decision.

Approved 2026-10-15 (D1–D8 as proposed; D9–D13 resolve Q3–Q7 with the recommended options).

| # | Decision | Rationale |
|---|---|---|
| D1 | The engine is a Rust port of libtorrent 2.0.11 (tag `v2.0.11`, BSD-3). No FFI, nothing linked. | Monolithic, lean, fully ours; libtorrent's proven algorithms and tests. |
| D2 | One network thread on **mio**. Protocols written sans-IO. Disk thread pool. Resolver thread. | libtorrent's own scaling model. mio is the smallest portable event loop (IOCP / epoll / kqueue). |
| D3 | Disk I/O uses pread/pwrite plus our own write-back cache. No mmap. | Avoids libtorrent 2.0's mmap memory and network-drive problems. Scales. |
| D4 | Dependencies: engine = `std` + `mio` + OS TLS; Win32 GUI = `windows-sys` only; everything else ported or written in-house. | Lean and monolithic; full control over size and performance. |
| D5 | Persistence: one resume DB + one metadata pack (like µTorrent's `resume.dat`), not two files per torrent. Lazy-load info dicts. | Startup time and RAM at 10k+ torrents. |
| D6 | Targets: Windows 10+ x64 (Rust's tier-1 baseline), Linux x86_64/aarch64, FreeBSD/OpenBSD. | Rust dropped pre-Windows-10 support from its tier-1 targets in 1.78. |
| D7 | Windows: static CRT, single `.exe`, portable mode (settings beside the exe), like µTorrent. | No installer or runtime needed. |
| D8 | Port libtorrent's tests with each module. Fuzz every parser. Deterministic swarm simulator. | Correctness without libtorrent's simulator. |
| D9 (Q3) | TLS is OS-native: SChannel on Windows, system OpenSSL / LibreSSL on Unix, behind a thin trait; Secure Transport (Security.framework) on macOS, which has no linkable OpenSSL (2026-10-21_225032_1792615832). | Almost no added binary size; the OS patches TLS. Built in `core::net::tls` with no new crates: SChannel through more `windows-sys` features, OpenSSL through hand-written declarations of a dozen stable functions, so Unix builds link the system `libssl` / `libcrypto` (Linux needs `libssl-dev` to build; FreeBSD has it in base). |
| D10 (Q4) | nox exposes a qBittorrent WebAPI v2-compatible subset (incremental `sync/maindata`). Since D18 it is a compatibility shim beside the native API, translating from the same cache; it never shapes a native feature. | Works with Sonarr, Radarr, Prowlarr and mobile apps. |

CI fuzzes each target on Linux: 2 min per push to main that touches the engine, 30 min weekly. | Nightly stays out of the product build (D12 still holds). Linux CI needs no ASan setup. |

| D42 | **Proposed** (2026-10-30_090053_1793347253; revisits D7, touches D16, D31, D40): **profiles and portable mode**, designed in [PROFILES.md](PROFILES.md). `--profile NAME` on all three binaries; the default profile is today's folder and a named one lives in `profiles/<name>` inside the same root (installed or portable). Fixes on the way: an unkeyed window lookup that can hand a torrent to the wrong copy, and two different portable tests (`exists()` / `is_file()`). Open questions Q1-Q9 in PROFILES.md. |
