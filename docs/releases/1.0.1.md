**PaTorrent 1.0.1** is the first stable release. It follows 1.0.0-rc.1 with no second candidate: the release candidate ran without trouble, and what changed since is listed below. There is no 1.0.0 release: its tagged build stopped on a packaging check, and the version moved on rather than reuse the tag. It has been used mostly by its author so far, so reports of what breaks are very welcome.

PaTorrent (PatinaTorrent) is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.0.0-rc.1

- **A Windows installer** beside the portable zip: for you alone (no administrator rights, into `%LOCALAPPDATA%\Programs\PaTorrent`) or for all users (into Program Files, through UAC), with a Start menu entry, an optional desktop shortcut and `.torrent` / `magnet:` associations, in-place upgrades and an uninstaller that keeps your settings unless you ask.
- **An update check that only tells.** 10 seconds after the start and every 12 hours, the Windows and GTK GUIs read a small list of releases from the [website](https://balls0fsteel.github.io/PaTorrent/). A newer version shows for a minute in the status bar and in the Logger; a click opens its release page. Nothing is downloaded or installed for you. Help > Check for Updates asks at once; Preferences > General > Privacy turns the automatic check off. The Flatpak leaves updating to Flathub. 1.0.0-rc.1 has no check, so its users have to fetch this release by hand.
- **The version where µTorrent showed it:** the window title, the tray tooltip, the Web UI's tab and the Windows executables' file properties.
- **Help > PaTorrent Website**, and the [website](https://balls0fsteel.github.io/PaTorrent/) itself: downloads with how to start each file, an FAQ and the documentation.

Settings and torrents from 1.0.0-rc.1 carry over unchanged.

## First run

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Running a newer setup later upgrades in place. Settings and torrents are in `%APPDATA%\PaTorrent`.
- **Windows zip.** Unzip anywhere and start `patorrent.exe` (SmartScreen as above). Settings and torrents go to `%APPDATA%\PaTorrent`; an empty `patorrent.ini` next to the exe keeps them beside it instead (portable mode).
- **Linux AppImage.** `chmod +x PaTorrent-1.0.1-x86_64.AppImage`, then run it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/patorrent/gtk`, torrents in `~/.local/share/patorrent/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user PaTorrent-1.0.1-x86_64.flatpak
  flatpak run io.github.balls0fsteel.PaTorrent
  ```

- **macOS.** Drag `PaTorrent.app` to Applications. It is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time ("cannot be opened because the developer cannot be verified"): right-click (or Control-click) the app > Open, then Open. Or remove the quarantine flag: `xattr -dr com.apple.quarantine /Applications/PaTorrent.app`. The GUI is Apple silicon only; Intel Macs get `patorrent-nox`.
- **Headless.** `patorrent-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080 (`--webui-https` for a self-signed certificate). `patorrent-nox add file.torrent --save DIR` adds a torrent. Running it as a service (systemd units, FreeBSD rc.d, `--daemon`, a Windows service) is described in [docs/DAEMON.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.0.1/docs/DAEMON.md).
- **Remote control.** Either GUI can drive a `patorrent-nox` elsewhere: File > Connect to Remote..., or start it with `--remote`.

## What is in it

- **Engine:** downloads and seeds over TCP and uTP, with HTTP, HTTPS and UDP trackers, magnet links, DHT, peer exchange, local peer discovery, protocol encryption, web seeds, SOCKS and HTTP proxies, UPnP / NAT-PMP port mapping, IP filters, super-seeding, sequential download and per-torrent speed limits. BitTorrent v2 and hybrid torrents (BEP 52), including creating them.
- **Windows GUI** (`patorrent`): the µTorrent 2.2.1 main window with its category list, every column, the detail tabs (General, Trackers, Peers, Pieces, Files, Speed, Logger), Preferences, Add New Torrent, Create New Torrent, Torrent Properties, the RSS downloader, the scheduler, Auto Shutdown, the tray icon, file and magnet associations and autostart.
- **GTK 4 GUI** (`patorrent-gtk`, Linux / BSD / macOS): the same main window and dialogs on the shared frontend model, with the tray, notifications, associations and autostart (through the Background portal in a Flatpak).
- **Daemon** (`patorrent-nox`): headless operation, its own Web UI, a qBittorrent-compatible Web API subset so existing tools can talk to it, HTTPS, and service integration (systemd units, a FreeBSD rc.d script, a Windows service).
- **34 languages**, including right-to-left layouts; the translations are machine-made and unreviewed, so corrections are welcome.
- Scale: on the author's PC the Windows GUI lists 100,000 torrents in about a second with idle GUI CPU under 0.1 %.

## Known limitations

- Most features have been exercised by the author only; some dialogs and settings have had little use. Keep a copy of torrents you care about elsewhere.
- **Do not use it on private trackers yet.** The client ID `PA` is not whitelisted anywhere.
- Nothing is code-signed: Windows SmartScreen and macOS Gatekeeper warn (see above).
- The installer is new: every build installs, checks and uninstalls it silently, but its wizard and the all-users path have had little hand testing.
- macOS: the `.app` has only been built and started on GitHub's runners; it has not been used on a real Mac. Window content, opening files and magnets from Finder, Login Items and the menu-bar icon are unverified.
- The Linux AppImages and the Flatpak have had command-line smoke checks but little desktop use; the aarch64 builds are untried on real hardware.
- The 100,000-torrent target has been measured on one mid-range PC only.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/PaTorrent/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, the Logger tab or `patorrent-nox run --verbose` output helps.
