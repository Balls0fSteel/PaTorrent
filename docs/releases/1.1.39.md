**PaTorrent 1.1.39** brings a gamer mode that keeps your ping low while it downloads, and smart disk I/O: gentle rechecks, drive type detection and, if you want it, slowing down while a disk is busy. The Windows GUI now updates itself. When you close it, both GUIs show what PaTorrent is still doing instead of looking stuck. The Files tab gets µTorrent 2.2.1's menu, completed downloads can move into a folder named after their label, and the engine carries the fixes from libtorrent 2.0.12 to 2.1.2 that apply to it. Everything else is as in 1.1.17. It has been used mostly by its author so far, so reports of what breaks are very welcome.

PaTorrent (PatinaTorrent) is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.1.17

- **Gamer mode: keep ping low.** Preferences > Bandwidth has 2.2.1's Global Rate Limit Options in all three frontends:
  - **"Keep ping low (limit speeds automatically)"** (off by default) pings the first router past your line and slows uploads and downloads down as soon as its queue grows, then speeds them up again when it clears. Your own limits stay as they are; the lower one applies. The status bar shows the automatic limit, as in "(auto 450 kB/s)".
  - On a test line with half a second of buffer, the ping fell from about 480 ms to 9-10 ms while PaTorrent kept 80-92% of the line's speed.
  - It pings on Windows, Linux and macOS. On Linux, the `net.ipv4.ping_group_range` setting must allow it; the Logger says so when it does not. On FreeBSD and OpenBSD, and wherever pings get no answer, it uses the delays measured by three or more uTP peers.
  - **"Apply rate limit to transport overhead"** (off) and **"Apply rate limit to uTP connections"** (on) work as in 2.2.1.
- **Smart disk I/O.** A new page, Preferences > Advanced > Disk I/O, in all three frontends:
  - **Gentle checks** (on by default). A check or recheck runs at the system's background disk priority and keeps other programs' files in memory. It also waits whenever its reads get clearly slower than usual, so it takes at most about half of a disk another program is using. On an idle disk it runs at full speed. **Limit checking to (MB/s)** caps it further (off by default).
  - **One check per drive, several drives at once.** Two torrents on one disk are checked one after the other, while torrents on different disks are checked side by side ("Drives checked at once", 4 by default).
  - **Drive types.** PaTorrent tells SSDs, hard disks, removable drives and network shares apart: on Windows and Linux from the system, on macOS from IOKit and on FreeBSD from GEOM. The Logger names what it found, for example "Disk I/O: drive D: (HDD, SATA)". With "Tune for the drive type" (on), a hard disk or removable drive gets at most two disk jobs at once and a network server four, so the disk does not waste its time seeking. A wrong guess can be corrected in `drive_overrides` in the Advanced table (`E:\=hdd, /mnt/nas=network`).
  - **When the disk is busy** (both off by default): "Slow downloads down (disk writes)" and "Slow uploads down (disk reads)". While a drive answers clearly more slowly than usual, the download or the upload is halved, and halved again while it stays slow. Once the drive is quiet, it grows back. The status bar shows the limit as "(auto ...)", and the Logger says which drive was busy.
- **Updates on Windows.**
  - The update box appears once for each new version. After that, a notice stays in the status bar until you click it.
  - In an installed copy, "Download and install" fetches the setup with a progress bar and checks it against the release's `SHA256SUMS`. It then closes PaTorrent, installs the update and starts it again. A portable copy opens the download page, as before.
- **Closing.**
  - **A closing window in both GUIs.** If closing takes more than a second, a window shows what PaTorrent is doing: stopping torrents, finishing moves (with a scrollable list and one progress bar), saving the torrent list and progress, or telling trackers. **Quit Now** cancels the moves, deletes their partial copies and leaves every torrent in its old folder. Saving the torrent list and progress is always allowed to finish.
  - **Signing out on Windows.** Windows now waits while PaTorrent saves, so a logoff or shutdown no longer loses progress. The GTK GUI does the same through the desktop's session manager, and SIGTERM and SIGINT now save before it quits.
  - **Starting it again while it closes** waits for the old copy to finish and then opens your torrents. Before, it gave up silently after 5 seconds.
- **Files tab menu**, as in µTorrent 2.2.1, in both GUIs:
  - Open, Open Containing Folder | Prioritize by File Order, Priority | Don't Download | Relocate...
  - A double click or Enter opens a file in its default program.
  - Prioritize by File Order gives the selected files falling priorities, so they finish in order. Relocate points one file at a new path and moves it there if it is on disk.
- **Label folders.** "Append the torrent's label" beside "Move completed downloads to:" (off by default; Windows, GTK and the Web UI) moves a finished labelled torrent to `<completed folder>\<label>`.
- **Engine fixes from libtorrent 2.0.12 to 2.1.2.** Every change in that range was checked against our engine, and the ones that apply were ported:
  - Requests for v2-only torrents are sized as newer libtorrent peers expect, and their piece layers can be fetched from us in every case.
  - A forced reannounce of a hybrid torrent announces both its hashes.
  - Renaming a file never overwrites another one. Resume data is about a third the size. If you go back to an older version, it rechecks each torrent once.
  - Web seeds request the right file names and drop their login on a redirect to another site. The IP filter applies to the DHT (on by default). Tracker URLs and path names in .torrent files are checked more strictly.
  - New engine options under Advanced: `dont_count_slow_torrents` works, plus `inactive_down_rate`, `inactive_up_rate`, `auto_manage_startup`, `natpmp_gateway` and `natpmp_lease_duration`.
- **Smaller additions:**
  - The Web UI's Bandwidth page names its rate limit options instead of showing their setting names.
  - "Show current speed in the title bar" (off) in both GUIs.
  - Preferences > Web UI in the Windows GUI sets the API key and the subnet whitelist that came with 1.1.17.
  - RSS feeds are fetched with conditional requests and gzip, so an unchanged feed costs almost nothing.
  - The qBittorrent importer takes each torrent's share limits as its seeding goal.
  - The qBittorrent-compatible API offers Torznab search to apps that use qBittorrent's search calls. The indexer's key never leaves PaTorrent.
- **Fixes:**
  - Session and torrent totals no longer count part of the traffic twice under a rate limit. They ran about half again too high before.
  - A check or recheck now stops promptly when its torrent is stopped. Watched folders are scanned off the GUI thread, so a slow network share cannot hold up the window.
- **Security.** The release review fixed 15 low-severity findings, each with a test. The self-update installs only the setup it checked, and a crafted search result can no longer make PaTorrent fetch a link on your own computer or local network. Details are in [SECURITY-REVIEW.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.39/docs/SECURITY-REVIEW.md).

Settings and torrents from 1.1.x carry over unchanged. The peer ID is now `-PA1012-`, because peers see the v2 hash and request changes. The remote protocol is now version 13, so a GUI and the `patorrent-nox` it drives must both be 1.1.39.

## First run

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Over an installed 1.0.1 or 1.1.x it upgrades in place. Settings and torrents are in `%APPDATA%\PaTorrent`.
- **Updating an installed 1.1.17.** 1.1.17 cannot install updates itself: its update box opens the download page, so run the new setup by hand once. From 1.1.39 on, the update box offers "Download and install".
- **Windows zip.** Unzip anywhere and start `patorrent.exe`; SmartScreen warns as above. Settings and torrents go to `%APPDATA%\PaTorrent`. An empty `patorrent.ini` next to the exe keeps them beside it instead (portable mode).
- **Gamer mode.** Tick Keep ping low in Preferences > Bandwidth. It first learns your line's idle ping, which takes up to about 20 seconds, so speeds may start lower.
- **Web UI from the Windows GUI.** In Preferences > Web UI, tick Enable Web UI, set a password and click OK. The page then shows the URL (`http://127.0.0.1:8080/` by default). For other computers, tick "Allow connections from other computers" and let the port through the Windows firewall. Use HTTPS when the connection leaves your home network.
- **Sonarr, Radarr, Prowlarr.** Add PaTorrent as a qBittorrent download client, with the Web UI's address, port, user name and password. If the app reaches PaTorrent by a host name rather than an IP address, add that name under Preferences > Web UI > Server domains (`webui.domain_list`).
- **Torrent search.** In your Prowlarr, copy an indexer's Torznab feed URL and the API key (Settings > General); in Jackett, use the `all` indexer's Torznab URL. Then open Manage Sources from the search box's menu (the Web UI: Find > Manage Sources), add the source and press Test.
- **Linux AppImage.** Run `chmod +x PaTorrent-1.1.39-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/patorrent/gtk`, torrents in `~/.local/share/patorrent/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user PaTorrent-1.1.39-x86_64.flatpak
  flatpak run io.github.balls0fsteel.PaTorrent
  ```

- **macOS.** Drag `PaTorrent.app` to Applications. It is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time ("cannot be opened because the developer cannot be verified"). Right-click (or Control-click) the app > Open, then click Open. Or remove the quarantine flag: `xattr -dr com.apple.quarantine /Applications/PaTorrent.app`. The GUI is Apple silicon only; Intel Macs get `patorrent-nox`.
- **Headless.** `patorrent-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080; add `--webui-https` for a self-signed certificate. `patorrent-nox add file.torrent --save DIR` adds a torrent. [docs/DAEMON.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.39/docs/DAEMON.md) describes running it as a service: systemd units, FreeBSD rc.d, `--daemon` and a Windows service.
- **Remote control.** Either GUI can drive a `patorrent-nox` elsewhere: use File > Connect to Remote..., or start it with `--remote`. Both sides must be 1.1.39.

## Known limitations

- Most features have been exercised by the author only; some dialogs and settings have had little use. Keep a copy of torrents you care about elsewhere.
- **Do not use it on private trackers yet.** The client ID `PA` is not whitelisted anywhere.
- Nothing is code-signed, so Windows SmartScreen and macOS Gatekeeper warn (see above).
- Keep ping low has been tested on a simulated slow line on Linux and with live pings on Windows, but not yet on a real line during a game, and not on a Mac.
- Smart disk I/O is new. Its drive detection has run on Windows (SSDs and a network drive) and Linux. On a Mac and on FreeBSD it has only been compiled. The busy-disk throttle's thresholds are first guesses, not yet measured on real hard disks and network shares, which is why it is off by default. On FreeBSD, USB disks are not recognised as removable.
- The self-update has been run end to end for one user on a clean Windows 11 machine. For an all-users installation, the administrator prompt it shows has not been tested.
- The closing window has been tested with real moves on Windows and on Linux (Xfce). Xfce does not let programs delay a logout, so there a logout does not wait for PaTorrent; other desktops have not been tried.
- The Files tab's new menu and the label folders are new in this release. In the GTK GUI they have not yet been used on a Linux desktop. Their texts, like the other new strings, are machine translations in every language but English.
- The Web UI served by the Windows GUI is covered by automated tests, a session on the author's PC and a Sonarr/Radarr/Prowlarr run, but not yet by wide use. The GTK GUI has no such page yet; on Linux and macOS the Web UI comes with `patorrent-nox`.
- Search has been run against Prowlarr; Jackett only through its documented answers. With Sonarr and Radarr, only `.torrent` grabs have been tested. Magnet grabs, "First" priority and Force Start have not. Tags are accepted but not kept.
- macOS: the `.app` has only been built and started on GitHub's runners; it has not been used on a real Mac.
- The Linux AppImages and the Flatpak have had command-line smoke checks but little desktop use; the aarch64 builds are untried on real hardware.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/PaTorrent/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, include the Logger tab or `patorrent-nox run --verbose` output. For security problems, see [SECURITY.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.39/SECURITY.md).
