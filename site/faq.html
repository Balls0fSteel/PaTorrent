What is PaTorrent?

A lean BitTorrent client in the spirit of µTorrent 2.2.1: small native programs, low RAM and CPU use, and a list that stays responsive with tens of thousands of torrents. The long name is PatinaTorrent; a patina is the good kind of rust, and PaTorrent is written in Rust.

There are three programs: patorrent, the native Windows GUI; patorrent-gtk, the GTK 4 GUI for Linux, BSD and macOS; and patorrent-nox, a headless daemon with its own Web UI for every platform. The engine is our own Rust port of libtorrent-rasterbar 2.0.11: libtorrent's code is the reference, nothing of it is linked.

PaTorrent is made by DukeCorp1996. The source is on GitHub.

Is it ready to use?

Mostly. 1.0.1 was the first stable release, and settings and torrents carry over from one version to the next. But it has been used mostly by its author so far, and some dialogs and settings have had little use, so keep a copy of anything you care about elsewhere, and please report what breaks.

What changed in each release is on the News page. Each release's notes list its known limitations, and what is still unchecked is in PLAN.md.

Where are my settings? What is portable mode?

Where each program keeps its settings and torrents

Windows GUI%APPDATA%\PaTorrent
Windows GUI, portable modeThe folder of patorrent.exe
GTK GUI on Linux and BSDSettings in ~/.config/patorrent/gtk, torrents in ~/.local/share/patorrent/gtk (or under $XDG_CONFIG_HOME and $XDG_DATA_HOME)
GTK GUI as a FlatpakThe same, under ~/.var/app/io.github.balls0fsteel.PaTorrent/ (config/ and data/)
GTK GUI on macOS~/Library/Application Support/PaTorrent/gtk
patorrent-noxA nox folder in the same places: %APPDATA%\PaTorrent\nox, ~/.config/patorrent/nox and ~/.local/share/patorrent/nox, or ~/Library/Application Support/PaTorrent/nox; as a service, see docs/DAEMON.md

Portable mode (Windows): put an empty file named patorrent.ini next to patorrent.exe, and PaTorrent keeps its settings and torrents in that folder instead of %APPDATA%, as µTorrent did. That way the whole folder can live on a USB stick. patorrent-nox.exe follows the same rule, in a nox folder there. Portable mode on every platform is planned for a later version.

Which languages does it speak?

English and 34 more: Arabic, Bulgarian, Catalan, Chinese (Simplified and Traditional), Croatian, Czech, Danish, Dutch, Finnish, French, German, Greek, Hebrew, Hungarian, Indonesian, Italian, Japanese, Korean, Norwegian Bokmål, Persian, Polish, Portuguese (Brazil and Portugal), Romanian, Russian, Serbian, Slovak, Spanish, Swedish, Thai, Turkish, Ukrainian and Vietnamese. Arabic, Hebrew and Persian use right-to-left layouts.

Every language is built into every program; there are no language files to download. By default PaTorrent follows your system's language; choose another in Preferences > General > Language (“User interface”), in the GUIs and in the Web UI alike.

The translations are machine-made and nobody has reviewed them yet. If yours reads oddly, please open an issue with a correction. Translators can try a table without rebuilding: PATORRENT_LANG=file.lng loads it.

How do the Web UI and remote mode work?

patorrent-nox is the headless daemon. With --webui it serves its own Web UI: the µTorrent 2.2.1 main window in a browser, with push updates instead of polling, keyboard shortcuts, a dark mode and a layout for phones.

patorrent-nox run --webui 8080 --webui-pass PASS

That listens on 127.0.0.1 only; open http://127.0.0.1:8080 and log in as admin. To use it from other machines, give an address (--webui 0.0.0.0:8443) and serve it over HTTPS with --webui-https, which makes a self-signed certificate on first use; compare the fingerprint your browser shows with the certificate SHA-256 line the daemon prints.

From the Windows GUI (1.1.7 and later): Preferences > Web UI serves the same page from patorrent.exe itself, over that window's torrents, as µTorrent did. Tick Enable Web UI, set a password and OK; the page shows the URL (http://127.0.0.1:8080/ by default). "Allow connections from other computers" listens on every address (let the port through the firewall), and "Use HTTPS" makes a self-signed certificate. Labels and settings changed in the browser show up in the window, and the other way round. From 1.1.17 the page's RSS Downloader edits the window's own feeds and filters; the alternative speed limits stay in the window. The GTK GUI has no such page yet.

Remote mode: either desktop GUI can drive a patorrent-nox on another machine, through the same port. Choose File > Connect to Remote..., or start the GUI with --remote, and give the host, port, login and whether to use HTTPS. A certificate your system does not trust is shown by its fingerprint and remembered once you accept it. The window then works on the remote daemon's torrents; the password is never stored.

The same port also serves a subset of qBittorrent's Web API, for tools written for qBittorrent (such as Sonarr, Radarr or Prowlarr). It is a subset, so not every call is there. Running the daemon as a service: docs/DAEMON.md; the design: docs/WEBUI.md.

How do I search for torrents?

From 1.1.17, through a Prowlarr or Jackett you run yourself. PaTorrent asks them over Torznab, the search API they share; it has no search plugins or site scrapers of its own, so nothing breaks when a site changes. Search works in the Windows GUI, the GTK GUI and the Web UI.

  1. Get a Torznab URL and the API key. In Prowlarr, copy an indexer's Torznab feed URL, and the API key from Settings > General. In Jackett, use the all indexer's Torznab URL and Jackett's API key.
  2. Open Manage Sources from the menu beside the search box (the arrow beside it on Windows; in the Web UI, Find > Manage Sources), add the source and press Test.
  3. Pick a source, or All sources, type in the search box and press Enter. In the results, sort them and add the ones you want.

API keys are stored encrypted on Windows and never shown again. Proxy: a source on this computer or your local network is reached directly; a public one goes through the proxy, if you set one (Preferences > Connection).

Can Sonarr, Radarr or Prowlarr use PaTorrent?

Yes, as a qBittorrent download client: turn on the Web UI (above), then in Sonarr, Radarr or Prowlarr add a download client of type qBittorrent with PaTorrent's host, port, user name and password. This works with patorrent-nox and with the Windows GUI's Web UI. Categories are PaTorrent's labels, and an add without a folder goes to its category's folder. Tags are accepted but not kept.

API key and subnet whitelist (1.1.17 and later): Web UI Preferences > Authentication has an optional API key, which the apps send as Authorization: Bearer, and an optional list of subnets whose requests need no login. Both are off by default and need the current password to change. The whitelist never applies to requests that come through a proxy.

Host names, as in Docker: to block DNS rebinding attacks, the Web UI answers only requests addressed to an IP address, localhost or a name you allowed. If the other program reaches PaTorrent by a host name (http://patorrent:8080, http://nas.lan:8080), its connection test fails with "unexpected Host header". Open the Web UI by IP address, then add the name in Preferences > Web UI > Server domains (for example patorrent;*.lan); from 1.1.17 the Windows GUI's own Preferences > Web UI has the same field. Or give the other program the IP address instead.

Remove Completed (1.1.7 and later) removes a download once PaTorrent has stopped it at its seeding goal (Preferences > Queueing > Seeding Goal, or the ratio and time the indexer asks for). A goal set to limit the upload rate instead keeps the torrent seeding, so nothing is removed.

What does PaTorrent send, and to whom?

The update check. From 1.0.1 on, PaTorrent checks for a newer release when it starts and every 12 hours after that. It downloads one small text file, https://balls0fsteel.github.io/PaTorrent/update.txt, which names the newest versions, and compares them with its own. The request carries only the User-Agent PaTorrent/<version>: no ID, no settings, nothing about your torrents. As with any web request, GitHub, which hosts this site, sees your IP address. If a newer version is out, PaTorrent asks once and keeps a note in its status bar; nothing is downloaded without your yes. A PaTorrent installed by the Windows setup can then fetch the new setup and the release's SHA256SUMS from GitHub, check the file, close and install over itself; a portable copy and the GTK GUI open the release page instead.

To turn the check off: Preferences > General > Privacy. From 1.1.17 patorrent-nox checks too, prints a line and shows a link in its Web UI when a newer version is out; start it with --no-update-check, or turn it off in the Web UI's Preferences > General > Privacy.

Torrent search asks only the Prowlarr or Jackett sources you added. A public source is reached through your proxy, if you set one; a source on your own machine or network is reached directly.

BitTorrent itself. Like every BitTorrent client, PaTorrent tells the trackers, the DHT and the peers of your torrents your IP address, and they can see what you download and share. A proxy (Preferences > Connection) can carry that traffic instead.

This website sets no cookies, has no analytics or trackers, and loads nothing from other sites. GitHub Pages serves it, under GitHub's privacy statement.

Can I use it on private trackers?

Not yet. Private trackers accept only clients they have whitelisted, and PaTorrent's client ID, PA, is not whitelisted anywhere yet. PaTorrent always reports itself honestly as PaTorrent (it never borrows another client's ID), so using it there could get an account into trouble. Registering the ID with the client lists is still to do.

Why do Windows and macOS warn about it?

The programs are not code-signed. So Windows SmartScreen says “Windows protected your PC” the first time (More info > Run anyway), and macOS Gatekeeper refuses the ad-hoc signed app until you open it with a right-click. The download page has the steps. To check that a file is the one that was published, compare its checksum.

How do I report a problem?

Open an issue on GitHub with your system, the file you downloaded and what happened. For a crash or a stuck torrent, the Logger tab or the output of patorrent-nox run --verbose helps.
