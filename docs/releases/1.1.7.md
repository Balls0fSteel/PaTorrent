**PaTorrent 1.1.7** gives the Windows GUI a Web UI of its own and makes PaTorrent a working download client for Sonarr, Radarr and Prowlarr. Preferences > Web UI starts the same Web UI `patorrent-nox` serves, inside `patorrent.exe`, over that window's torrents, as µTorrent and qBittorrent do. The *arr apps' seed limits now arrive with each grab and their Remove Completed works, against both `patorrent-nox` and the Windows GUI. Everything else is 1.1.0. It has been used mostly by its author so far, so reports of what breaks are very welcome. (1.1.2 was drafted but never published; this release includes it.)

PaTorrent (PatinaTorrent) is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.1.0

- **Web UI in the Windows GUI.** Preferences > Web UI has these settings, and the Web UI is off by default:
  - Enable Web UI;
  - a user name and password (the password is stored hashed);
  - the listening port;
  - "Allow connections from other computers";
  - "Use HTTPS (self-signed certificate)".

  With it on, a browser at the URL the page shows logs in and sees this window's torrents. From the browser you can add, start, stop, pause, label and remove torrents, change the rate limits and most other preferences, and shut the client down. Changes made in the browser appear in the window within a second, and changes made in the window appear in the browser. The Web UI starts with the program when enabled, and its settings are `webui.*` keys in `patorrent.ini`. In this mode the page has no RSS Downloader and no alternative speed limits; the window keeps those.
- **Sonarr, Radarr and Prowlarr.** These were tested against the real apps, both with `patorrent-nox` and with the Windows GUI's Web UI.
  - The per-indexer seed ratio and seed time the apps send with a grab become that torrent's seeding goal.
  - Each torrent's limits and the global goal are reported back to the apps, so their "Remove Completed" removes a torrent once PaTorrent has stopped it.
  - Removing a category from the Web UI now clears the window's label too.
- **Clearer Host-check error.** A Web UI or API request that names the client by a host name it does not know (as an app in Docker often does) is still refused. The error now says how to allow that name: open the page by IP address and add the name under Preferences > Web UI > Server domains.
- **Idle seeds keep their seeding time.** A seed without peers now advances its seeding time each minute, so a time-based seeding goal stops it on time. Before this, its time stood still until a peer came.
- **Adding a torrent brings the window forward.** Opening a `.torrent` or magnet while PaTorrent runs now activates its window, as µTorrent's UI Settings > "Activate the program window" does; this is on by default. A torrent added stopped reads Stopped instead of "Checking 0.0 %".
- **nox service on Windows.** `patorrent-nox service install` now stores the `--webui-user` / `--webui-pass` login hashed in its state folder. Before, it was on the service's command line, which every local user could read. `--replace` removes an installed service first and `--now` starts the new one, so a changed setup is one command.

Settings and torrents from 1.1.0 carry over unchanged. The remote protocol is still version 9, so for remote mode a GUI and a `patorrent-nox` must both be 1.1.0 or newer. The peer ID stays `-PA1011-`, because nothing changed on the wire.

## First run

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Over an installed 1.0.1 or 1.1.0 it upgrades in place. Settings and torrents are in `%APPDATA%\PaTorrent`.
- **Windows zip.** Unzip anywhere and start `patorrent.exe`; SmartScreen warns as above. Settings and torrents go to `%APPDATA%\PaTorrent`. An empty `patorrent.ini` next to the exe keeps them beside it instead (portable mode).
- **Web UI from the Windows GUI.** In Preferences > Web UI, tick Enable Web UI, set a password and click OK. The page then shows the URL (`http://127.0.0.1:8080/` by default). For other computers, tick "Allow connections from other computers" and let the port through the Windows firewall. Use HTTPS when the connection leaves your home network.
- **Sonarr, Radarr, Prowlarr.** Add PaTorrent as a qBittorrent download client, with the Web UI's address, port, user name and password. If the app reaches PaTorrent by a host name rather than an IP address, add that name under Preferences > Web UI > Server domains (`webui.domain_list`).
- **Linux AppImage.** Run `chmod +x PaTorrent-1.1.7-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/patorrent/gtk`, torrents in `~/.local/share/patorrent/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user PaTorrent-1.1.7-x86_64.flatpak
  flatpak run io.github.balls0fsteel.PaTorrent
  ```

- **macOS.** Drag `PaTorrent.app` to Applications. It is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time ("cannot be opened because the developer cannot be verified"). Right-click (or Control-click) the app > Open, then click Open. Or remove the quarantine flag: `xattr -dr com.apple.quarantine /Applications/PaTorrent.app`. The GUI is Apple silicon only; Intel Macs get `patorrent-nox`.
- **Headless.** `patorrent-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080; add `--webui-https` for a self-signed certificate. `patorrent-nox add file.torrent --save DIR` adds a torrent. [docs/DAEMON.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.7/docs/DAEMON.md) describes running it as a service: systemd units, FreeBSD rc.d, `--daemon` and a Windows service.
- **Remote control.** Either GUI can drive a `patorrent-nox` elsewhere: use File > Connect to Remote..., or start it with `--remote`. Both sides must be 1.1.0 or newer.

## Known limitations

- Most features have been exercised by the author only; some dialogs and settings have had little use. Keep a copy of torrents you care about elsewhere.
- **Do not use it on private trackers yet.** The client ID `PA` is not whitelisted anywhere.
- Nothing is code-signed, so Windows SmartScreen and macOS Gatekeeper warn (see above).
- The Web UI served by the Windows GUI is new. It is covered by automated tests, a session on the author's PC and a Sonarr/Radarr/Prowlarr run, but not yet by wide use. The GTK GUI has no such page yet; on Linux and macOS the Web UI comes with `patorrent-nox`.
- With Sonarr and Radarr, only `.torrent` grabs have been tested. Magnet grabs, "First" priority and Force Start have not. Tags are not supported, so the apps log a warning when they send one.
- The search box and the importers have had little hand testing. The importers have been tested against qBittorrent's and µTorrent's file formats, but not yet against many real installations.
- The GTK GUI's icons have been built and checked on CI but not yet looked at on a Linux desktop.
- macOS: the `.app` has only been built and started on GitHub's runners; it has not been used on a real Mac.
- The Linux AppImages and the Flatpak have had command-line smoke checks but little desktop use; the aarch64 builds are untried on real hardware.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/PaTorrent/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, include the Logger tab or `patorrent-nox run --verbose` output. For security problems, see [SECURITY.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.7/SECURITY.md).
