## 2026-10-30_072342_1793345022: Adding a torrent activates the window; a torrent added stopped reads Stopped (1.1.7)

- **Bug (owner):** opening a `.torrent` or magnet while PaTorrent ran left its window behind. The running instance did call `SetForegroundWindow`, but Windows' foreground lock refuses a background process; the second instance (started by the user's click) now hands its right over with `AllowSetForegroundWindow` before forwarding. µTorrent 2.2.1 has this as UI Settings > When Adding Torrents > "Activate the program window" (on by default); PaTorrent gains it as `ui.activate_on_add` (Win32 and GTK Preferences, shared `pref_pages`). Off, only the Add New Torrent dialog comes up, which now raises itself. The Web UI keeps a host's value and does not show it.
- **Bug (owner):** a torrent added stopped read "Checking 0.0 %": the engine creates torrents in `CheckingResumeData` and leaves it only when started. `status_text`, `status_class` and `status_icon` now treat a stopped or paused (not auto-managed) torrent in a checking state as Stopped / Paused, in all three frontends. The engine and the qBittorrent shim's `checkingResumeData` (as qBittorrent reports it) are unchanged.
- **Tests:** status text, class and icon cases for stopped and paused checking states; the new option's default and round-trip in the options tests.

## 2026-10-29_162347_1793287427: The shim keeps and reports seed limits for the *arr apps (1.1.3)

- **Fixed (INTEGRATIONS.md gaps 1-2):** `torrents/add` keeps `ratioLimit` / `seedingTimeLimit` as the torrent's own seeding goal (the *arr apps send them there, not via `setShareLimits`, at our WebAPI 2.11.2). `torrents/info` and `sync/maindata` report each torrent's `ratio_limit` / `seeding_time_limit` (`-2` without its own goal, `-1` for a target that is off), and `app/preferences` reports the global goal as `max_ratio_enabled`, `max_ratio`, `max_seeding_time_enabled`, `max_seeding_time` and `max_ratio_act: 0`. The limits are enabled only when the goal stops torrents, not when it caps their upload. With this, Sonarr's and Radarr's Remove Completed can remove a stopped torrent. `setShareLimits` now marks the torrent changed, so `sync/maindata` sends the new limits. `commands::share_goal` is shared by both paths.
- **Validation:** new `the_arr_apps_share_limits_round_trip` (an *arr-style add with `True` and limits, `setShareLimits`, the maindata diff, the preferences with both goal actions); all nox tests pass (154), workspace clippy and fmt clean. Not yet run against a real Sonarr or Radarr. Version 1.1.3 (D37); peer ID unchanged.
