## 2026-11-04_101641_1793783801: Version 1.1.57: help text for settings and controls (D55)

- **D55 (built by an Opus 5.5 agent, reviewed and merged):** a help table beside the string table (`lang::H`, `help!(Key)`), keyed like the labels. The English is compiled in, deflated from `en.lng`'s `help.` lines (13.2 KB); translations may carry `help.` lines and fall back to English. 302 texts written from the code cover every Preferences control, every Advanced row, the main menus and the toolbar, each with a note naming the code it was read from; `docs/HELP_TEXTS.md` lists them for review and is generated by a test, and a test fails any control without help. `help::WIKI_URL` is the single place for the wiki's address.
- Win32: one tooltip control per dialog (0.7 s delay, 20 s shown, greyed controls through rectangle tools), a description pane under the Preferences pages following hover, then focus (the Advanced page's selected row), F1 as a tracking tip beside the focused control, the hint line beside the buttons, and menu and toolbar help in the status bar while highlighted. The Preferences dialog grew from 301 to 343 dialog units. GTK: tooltips, the pane, F1 through a `GtkShortcut`. Web UI: `help` (and `wiki` once set) on every `GET /pa/prefs` field, `title` attributes, the pane, F1.
- **Checked:** fmt, clippy and the frontend, nox and Win32 tests here (new tests: every page control and Advanced row has help, the pane and labels follow focus, every menu item and toolbar button has help); GTK clippy with `-D warnings` and its 29 tests on the Xubuntu VM; hidden-desktop screenshots of the pane, the hint and a menu item's help in the status bar. Not run: hover tooltips and the real F1 key (only their unit tests), the GTK window, the Web UI page. Found while writing the texts: `hashing_threads`, `tracker_receive_timeout` and `request_timeout` are read by nothing, and `max_queued_disk_bytes` acts as at least 4 MB (BACKLOG).
- Open: tooltips in the other dialogs (Add, Properties, RSS), help for GTK's main-menu items.

## 2026-11-04_095851_1793782731: Version 1.1.56: the Files tab's quick filter (D50)

- **D50 (built by an Opus 5.5 agent, reviewed and merged):** the Files tab has a quick filter in all three UIs: a "Filter files" box at its top right lists only the files whose path (folders included) has every word typed, ignoring case, with "12 of 3,400 files" beside it. Escape clears it, Ctrl+F from the Files tab goes to it, Ctrl+A selects the shown files (Win32 and GTK used to select torrents there). The text stays when another torrent is selected and is never stored. Shared `frontend::detail::FileFilter`; `Detail.file_rows` holds the filtered rows, so the menus, Open, Relocate and the double click follow it. Prioritize by File Order orders all of the torrent's files while a filter is on. Two strings in every language table. Assumed answers: the text is kept across torrents and the box is always visible.
- **Checked:** fmt, clippy and the frontend, nox and Win32 tests here; GTK clippy and an Xvfb run with snapshots on the Xubuntu VM; a hidden `--demo 20` Win32 run with screenshots. Not run: the Web UI in a browser, Prioritize by File Order with a filter on, a remote window, 150-200 % DPI.
