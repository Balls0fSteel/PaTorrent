**PaTorrent 1.1.2** gives the Windows GUI a Web UI of its own: Preferences > Web UI starts the same Web UI `patorrent-nox` serves, inside `patorrent.exe`, over that window's torrents, as µTorrent and qBittorrent do. The daemon's Windows service command stores the Web UI login hashed and can replace and start an installed service in one step. Everything else is 1.1.0. It has been used mostly by its author so far, so reports of what breaks are very welcome.

PaTorrent (PatinaTorrent) is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.1.0

- **Web UI in the Windows GUI.** Preferences > Web UI has Enable Web UI, a user name and password, the listening port, "Allow connections from other computers" and "Use HTTPS (self-signed certificate)". With it on, a browser at the URL the page shows logs in and sees this window's torrents: it can add, start, stop, pause, label and remove them, change the rate limits and most other preferences, and shut the client down. Labels, pause marks and settings changed in the browser appear in the window within a second, and the window's changes in the browser. The Web UI starts with the program when enabled and is off by default. The settings are `webui.*` keys in `patorrent.ini`; the password is stored hashed. The page has no RSS Downloader and no alternative speed limits in this mode (the window keeps those); the qBittorrent-compatible API answers as before, so a tool that drives qBittorrent can drive the window.
- **nox service on Windows.** `patorrent-nox service install` stores the `--webui-user` / `--webui-pass` login hashed in its state folder instead of on the service's command line, which every local user could read. `--replace` removes an installed service first and `--now` starts the new one, so a changed setup is one command.

Settings and torrents from 1.1.0 carry over unchanged. The remote protocol is still version 9: a GUI and a `patorrent-nox` must both be 1.1.0 or newer to work together in the remote mode. The peer ID stays `-PA1011-`: nothing changed on the wire.

## First run

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Over an installed 1.0.1 or 1.1.0 it upgrades in place. Settings and torrents are in `%APPDATA%\PaTorrent`.
- **Windows zip.** Unzip anywhere and start `patorrent.exe` (SmartScreen as above). Settings and torrents go to `%APPDATA%\PaTorrent`; an empty `patorrent.ini` next to the exe keeps them beside it instead (portable mode).
- **Web UI from the Windows GUI.** Preferences > Web UI: tick Enable Web UI, set a password, OK; the page then shows the URL (`http://127.0.0.1:8080/` by default). For other computers tick "Allow connections from other computers" and let the port through the Windows firewall; use HTTPS when the connection leaves your home network.
- **Linux AppImage.** `chmod +x PaTorrent-1.1.2-x86_64.AppImage`, then run it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/patorrent/gtk`, torrents in `~/.local/share/patorrent/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user PaTorrent-1.1.2-x86_64.flatpak
  flatpak run io.github.balls0fsteel.PaTorrent
  ```

- **macOS.** Drag `PaTorrent.app` to Applications. It is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time ("cannot be opened because the developer cannot be verified"): right-click (or Control-click) the app > Open, then Open. Or remove the quarantine flag: `xattr -dr com.apple.quarantine /Applications/PaTorrent.app`. The GUI is Apple silicon only; Intel Macs get `patorrent-nox`.
- **Headless.** `patorrent-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080 (`--webui-https` for a self-signed certificate). `patorrent-nox add file.torrent --save DIR` adds a torrent. Running it as a service (systemd units, FreeBSD rc.d, `--daemon`, a Windows service) is described in [docs/DAEMON.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.2/docs/DAEMON.md).
- **Remote control.** Either GUI can drive a `patorrent-nox` elsewhere: File > Connect to Remote..., or start it with `--remote`. Both sides must be 1.1.0 or newer.

## Known limitations

- Most features have been exercised by the author only; some dialogs and settings have had little use. Keep a copy of torrents you care about elsewhere.
- **Do not use it on private trackers yet.** The client ID `PA` is not whitelisted anywhere.
- Nothing is code-signed: Windows SmartScreen and macOS Gatekeeper warn (see above).
- The Web UI served by the Windows GUI is new: it is covered by automated tests and a session on the author's PC, not yet by wide use. The GTK GUI has no such page yet; on Linux and macOS the Web UI comes with `patorrent-nox`.
- The search box and the importers have had little hand testing; the importers have been tested against qBittorrent's and µTorrent's file formats, not yet against many real installations.
- The GTK GUI's icons have been built and checked on CI but not yet looked at on a Linux desktop.
- macOS: the `.app` has only been built and started on GitHub's runners; it has not been used on a real Mac.
- The Linux AppImages and the Flatpak have had command-line smoke checks but little desktop use; the aarch64 builds are untried on real hardware.

## Reporting problems

For a crash or a stuck torrent, the Logger tab or `patorrent-nox run --verbose` output helps. Security problems: see [SECURITY.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.2/SECURITY.md).
