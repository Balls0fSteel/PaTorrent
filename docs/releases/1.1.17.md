**PaTorrent 1.1.17** adds torrent search through your own Prowlarr or Jackett, in the Windows GUI, the GTK GUI and the Web UI. It also gives the Windows GUI's Web UI the RSS Downloader, and gives `patorrent-nox` an update check like the GUIs'. For Sonarr, Radarr and Prowlarr there is an optional API key and subnet whitelist, plus a few smaller fixes. Everything else is 1.1.7. It has been used mostly by its author so far, so reports of what breaks are very welcome.

PaTorrent (PatinaTorrent) is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.1.7

- **Torrent search (Torznab).** PaTorrent searches through the Prowlarr or Jackett you already run. It has no search plugins or site scrapers of its own, so nothing breaks when a site changes.
  - **Windows:** the arrow beside the toolbar's search box picks a source, or "All sources". Enter then opens Search Torrents, where results can be sorted and added.
  - **GTK:** the menu beside the search box does the same.
  - **Web UI:** a Find button beside the filter box opens the same search.
  - **Sources:** each source is a Torznab URL, with Prowlarr's per-indexer URL or Jackett's `all` URL, and its API key. Manage Sources adds, edits, tests and switches them.
  - **API keys** are stored encrypted on Windows and never shown again.
  - **Proxy:** a source on this computer or your local network is reached directly; a public one goes through the proxy, if you set one.
- **RSS in the Windows GUI's Web UI.** The page's RSS Downloader edits the window's own feeds and filters, and its downloads go through the window's Add dialog rules.
- **Sonarr, Radarr and Prowlarr:**
  - **API key and subnet whitelist:** Web UI Preferences > Authentication has an optional API key, sent as `Authorization: Bearer`, and an optional list of subnets that need no login. Both are off by default and need the current password to change. The whitelist never applies to requests that come through a proxy.
  - **Category folders:** an add without a folder now goes to its category's folder.
  - **Unused categories:** in the Windows GUI's Web UI, a category no torrent uses yet survives a restart.
  - **Tags:** tag requests are accepted, and ignored, so the apps stop logging warnings.
- **Windows Web UI settings:** Preferences > Web UI has a Server domains field, for apps that reach PaTorrent by a host name.
- **Update check in `patorrent-nox`.** Like the GUIs, it reads the website's list of releases shortly after it starts and every 12 hours, and prints a line and shows a link in the Web UI when a newer version is out. `--no-update-check`, or the Web UI's General > Privacy setting, turns it off.

Settings and torrents from 1.1.x carry over unchanged. The remote protocol is still version 9. The peer ID stays `-PA1011-`, because nothing changed on the wire.

## First run

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Over an installed 1.0.1 or 1.1.0 it upgrades in place. Settings and torrents are in `%APPDATA%\PaTorrent`.
- **Windows zip.** Unzip anywhere and start `patorrent.exe`; SmartScreen warns as above. Settings and torrents go to `%APPDATA%\PaTorrent`. An empty `patorrent.ini` next to the exe keeps them beside it instead (portable mode).
- **Web UI from the Windows GUI.** In Preferences > Web UI, tick Enable Web UI, set a password and click OK. The page then shows the URL (`http://127.0.0.1:8080/` by default). For other computers, tick "Allow connections from other computers" and let the port through the Windows firewall. Use HTTPS when the connection leaves your home network.
- **Sonarr, Radarr, Prowlarr.** Add PaTorrent as a qBittorrent download client, with the Web UI's address, port, user name and password. If the app reaches PaTorrent by a host name rather than an IP address, add that name under Preferences > Web UI > Server domains (`webui.domain_list`).
- **Torrent search.** In your Prowlarr, copy an indexer's Torznab feed URL and the API key (Settings > General); in Jackett, use the `all` indexer's Torznab URL. Then open Manage Sources from the search box's menu (the Web UI: Find > Manage Sources), add the source and press Test.
- **Linux AppImage.** Run `chmod +x PaTorrent-1.1.17-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/patorrent/gtk`, torrents in `~/.local/share/patorrent/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user PaTorrent-1.1.17-x86_64.flatpak
  flatpak run io.github.balls0fsteel.PaTorrent
  ```

- **macOS.** Drag `PaTorrent.app` to Applications. It is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time ("cannot be opened because the developer cannot be verified"). Right-click (or Control-click) the app > Open, then click Open. Or remove the quarantine flag: `xattr -dr com.apple.quarantine /Applications/PaTorrent.app`. The GUI is Apple silicon only; Intel Macs get `patorrent-nox`.
- **Headless.** `patorrent-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080; add `--webui-https` for a self-signed certificate. `patorrent-nox add file.torrent --save DIR` adds a torrent. [docs/DAEMON.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.17/docs/DAEMON.md) describes running it as a service: systemd units, FreeBSD rc.d, `--daemon` and a Windows service.
- **Remote control.** Either GUI can drive a `patorrent-nox` elsewhere: use File > Connect to Remote..., or start it with `--remote`. Both sides must be 1.1.0 or newer.

## Known limitations

- Most features have been exercised by the author only; some dialogs and settings have had little use. Keep a copy of torrents you care about elsewhere.
- **Do not use it on private trackers yet.** The client ID `PA` is not whitelisted anywhere.
- Nothing is code-signed, so Windows SmartScreen and macOS Gatekeeper warn (see above).
- The Web UI served by the Windows GUI is new. It is covered by automated tests, a session on the author's PC and a Sonarr/Radarr/Prowlarr run, but not yet by wide use. The GTK GUI has no such page yet; on Linux and macOS the Web UI comes with `patorrent-nox`.
- Search has been run against Prowlarr; Jackett only through its documented answers. With Sonarr and Radarr, only `.torrent` grabs have been tested. Magnet grabs, "First" priority and Force Start have not. Tags are accepted but not kept.
- The search windows have been run against a test Prowlarr on Windows and Linux, but not yet at high DPI or in wide use. The importers have been tested against qBittorrent's and µTorrent's file formats, but not yet against many real installations.
- The GTK GUI's icons have been built and checked on CI but not yet looked at on a Linux desktop.
- macOS: the `.app` has only been built and started on GitHub's runners; it has not been used on a real Mac.
- The Linux AppImages and the Flatpak have had command-line smoke checks but little desktop use; the aarch64 builds are untried on real hardware.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/PaTorrent/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, include the Logger tab or `patorrent-nox run --verbose` output. For security problems, see [SECURITY.md](https://github.com/Balls0fSteel/PaTorrent/blob/v1.1.17/SECURITY.md).
