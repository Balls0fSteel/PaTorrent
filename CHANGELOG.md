## 2026-10-29_162347_1793287427: The shim keeps and reports seed limits for the *arr apps (1.1.3)

- **Fixed (INTEGRATIONS.md gaps 1-2):** `torrents/add` keeps `ratioLimit` / `seedingTimeLimit` as the torrent's own seeding goal (the *arr apps send them there, not via `setShareLimits`, at our WebAPI 2.11.2). `torrents/info` and `sync/maindata` report each torrent's `ratio_limit` / `seeding_time_limit` (`-2` without its own goal, `-1` for a target that is off), and `app/preferences` reports the global goal as `max_ratio_enabled`, `max_ratio`, `max_seeding_time_enabled`, `max_seeding_time` and `max_ratio_act: 0`. The limits are enabled only when the goal stops torrents, not when it caps their upload. With this, Sonarr's and Radarr's Remove Completed can remove a stopped torrent. `setShareLimits` now marks the torrent changed, so `sync/maindata` sends the new limits. `commands::share_goal` is shared by both paths.
- **Validation:** new `the_arr_apps_share_limits_round_trip` (an *arr-style add with `True` and limits, `setShareLimits`, the maindata diff, the preferences with both goal actions); all nox tests pass (154), workspace clippy and fmt clean. ## 2026-10-28_174137_1793205697: The Windows GUI serves its own Web UI (1.1.2, D40)

- **Request (owner):** mimic µTorrent and qBittorrent, "you have the client, and it can host a Web UI"; nox is an engine as a service. D39's page (1.1.1), which drove the nox service, showed another client's torrents; it is superseded the same day.
- **nox (`webui`): hosted mode.** `Config::hosted` with the `Host` trait and the host's preferences: the server stores nothing (`webui.json` untouched), reads the login from `webui.username` / `webui.password` (a hash) and the labels and pause marks from `torrent.<key>.*` on each torrent's first sight, runs none of its automations (scheduler, seeding goal, scrapes, `.torrent` folders, RSS, move-completed) and sends nothing to the engine from Preferences; what a browser changes (a label, a pause mark, a seeding goal, a Preferences page, the login) goes to the host as preference changes through `Shared::save`, and the host's changes come back through `WebUi::options_changed`. `hello` says `hosted`; the page hides RSS, the RSS endpoints answer 404, alternative speed limits are off. `prefs::restore` is split into a pure read-back and nox's applying part. Design: [WEBUI.md](docs/WEBUI.md) "Hosted by a desktop client".
- **frontend:** `Prefs` has a change journal (`track_changes`, `take_changes`, `apply_changes`, `stop_tracking`): only real changes, the plain values, and a clone starts empty.
- **Win32:** `webui_service.rs` is gone; `webui_host.rs` keeps the `webui.*` setup (`enabled`, `username`, `listen`, `https`, the hashed `password`), starts the server with a self-signed certificate in the settings folder for HTTPS, and is the host: a browser's changes are queued and `WM_APP_WEBUI` applies them on the GUI thread (labels and pause marks into the list by `InfoHashes::key_hex`, anything the Preferences dialog edits through the same path as its OK), a browser's shutdown exits as File > Exit. The window feeds every alert batch to the server, mirrors its preference changes once a second and after each batch, starts the server at start-up when enabled and stops it before the engine. Preferences > Web UI: the same fields; the status line says running with the URL, off, or why it could not start; a remote window has the page greyed. `patorrent` now links `patorrent-nox` as a library.
- **Strings:** `PrefWebUiNote`, `WebUiRunning`, `WebUiStopped`, `WebUiFailed` rewritten, `WebUiRemoteWindow` added, four service-only keys removed, in the 35 tables (34 machine translations; hr/sr/hu/fi wording noted by the translator).
- **Validation:** frontend 199 tests, nox 153 (5 new in `tests/hosted.rs`: the journal both ways, the login from the host, no engine writes from Preferences, RSS and alt limits refused, shutdown), Win32 70 (`the_web_ui_page_runs_the_server` against a fake hook, the setup round trip), workspace clippy and fmt clean. Live on the demo build: the page reports running, the browser logs in and lists the window's 40 torrents without an RSS button, and a label set through `POST /pa/torrents/label` appears in the window's `patorrent.ini` and the page's tree within a second. Hand checks in BACKLOG. Version 1.1.2.
